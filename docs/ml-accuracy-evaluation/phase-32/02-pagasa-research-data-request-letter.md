I am [requester name], [program/institution], under [adviser name and contact],
preparing an academic study of rice-yield prediction for Lian, Batangas. We
request an authenticated historical climate dataset that can be matched to
approved Lian rice planting and harvest records. The request is for observed
data, not climatological normals, forecasts, or model-generated values.

Please advise the applicable PAGASA request form, fees, terms of use, and
research-approval documents. The official climate-data request route is
<https://pagasa.dost.gov.ph/climate/climate-data>. We will comply with the
required application and attribution conditions.

## Requested coverage and variables

Please provide all available compatible coverage for [start year]–[end year],
or state the actual period supplied, for the nearest approved station(s) or an
approved gridded product relevant to Lian. Requested variables, where
available, are:

- daily or monthly rainfall/precipitation, in millimetres;
- daily or monthly maximum, minimum, and mean air temperature, in degrees
  Celsius;
- station/grid identifier, coordinates, elevation, and observation timezone;
- observation date/time, aggregation rule, and crop-season window support;
- missing-value codes, quality flags, outlier corrections, and revised values;
- record creation/release date and any publication delay or availability rule;
- product version, source documentation, and data-license/permission terms.

The preferred alignment is by the approved planting-to-harvest window for each
MAO observation. Please do not aggregate or impute values without documenting
the method. If only a station proxy such as Ambulong is available, identify it
as a proxy and provide enough metadata for the adviser and agricultural
reviewer to approve or reject its use for Lian. Station proximity alone will
not be treated as evidence of Lian farm conditions.

## Certification and delivery requirements

Please include the custodian, extraction date, original format, checksum or
official file identifier, station/product metadata, units, missingness rules,
quality-control notes, revisions, and permission reference. The delivery should
be accompanied by a source statement confirming that the values are observed
records or identifying any modeled, interpolated, normal, or derived component.

The climate file will be delivered with the MAO package using the existing
[evidence manifest](../../data-audit/phase-11-evidence-manifest.example.json).
It will be quarantined and validated before any feature reconstruction. No
climate file will be imported into the active database or used to retrain the
deployed model.

Please contact [requester/contact] with the applicable request procedure and
whether the requested coverage is available.
