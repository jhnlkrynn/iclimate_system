### Detailed Findings

#### SEC-01 — `FarmerApprovalController` lacks `MaoScope` barangay enforcement ✅ Fixed
- **Area:** Security (Authorization / Scoping)
- **Severity:** **High**
- **Evidence:** `app/Http/Controllers/FarmerApprovalController.php:15-90` (`index`, `show`, `approve`, `reject`, `recoveryCode`) checks `$this->authorizeStaff($request)` (`$request->user()?->isMao() && $request->user()->hasApplicationAccess()`), without applying `MaoScope::apply(...)` or `MaoScope::canManageBarangay(...)` (unlike `FarmerProfileController` / `CrudController`, `FarmAssociationReviewController`, and `MaoAssociationReportController`).
- **Impact:** A barangay-scoped MAO staff user assigned to one barangay can view, approve, reject, or generate a one-time password recovery code for a farmer in any other barangay.
- **Proposed Fix:** Apply `MaoScope::apply($query, 'barangay', $request->user())` in `index()` and `abort_unless(MaoScope::canManageBarangay($user->barangay, $request->user()), 403)` in `show()`, `approve()`, `reject()`, and `recoveryCode()`.
- **Resolution:** Fixed on `fix/audit-phase-1` (`FarmerApprovalController` enforces `MaoScope` across `index`, `show`, `approve`, `reject`, `reconsider`, and `recoveryCode`; MAO Head and unscoped MAO retain full access). Verified by `tests/Feature/FarmerApprovalScopeTest.php`.

#### PRIV-01 — Missing Data Privacy Act (RA 10173) notice and consent ✅ Fixed
- **Area:** Privacy
- **Severity:** **High**
- **Evidence:** `resources/views/auth/partials/register-form.blade.php` and public pages have no RA 10173 Data Privacy notice or privacy policy link (`grep` across `resources/views/` and `lang/en/` found only `lang/en/farmer.php:673`, which covers farm map coordinates only).
- **Impact:** Farmers submit personal information (`name`, `email`, `contact_number`, `address`, `rsbsa_no`, farm coordinates) without an explicit statutory Data Privacy Act notice describing purpose, retention, and MAO access.
- **Proposed Fix:** Add a concise Data Privacy Act (RA 10173) notice and acknowledgment link on registration, mobile sign-up, and profile pages, and document retention periods (e.g., `deleted_at`, logs, backups).
- **Resolution:** Fixed on `fix/audit-phase-1` (added RA 10173 notice and required `"I agree"` consent checkbox saved with `privacy_agreed_at` on web and mobile sign-up, plus `/privacy-notice` in `en`/`fil` linked from the footer and profile page). Verified by `tests/Feature/DataPrivacyNoticeTest.php`.

#### PRIV-02 — Unredacted PII in `farmer_registration` report exports ✅ Fixed
- **Area:** Privacy
- **Severity:** **Medium**
- **Evidence:** `app/Services/Analytics/AnalyticsPayloadFactory.php:90` loads `FarmerProfile::query()->get()->toArray()`, and `app/Http/Controllers/ReportController.php:167-185` (`exportCsv`) plus `app/Http/Controllers/ReportExtrasController.php:36-73` (`xlsx`, `pdf`) export those columns directly without masking/hashing `contact_number` or `rsbsa_no`.
- **Impact:** Exported CSV/XLSX/PDF files contain plain-text farmer contact numbers and RSBSA numbers if downloaded and shared outside the system.
- **Proposed Fix:** Mask or omit `contact_number` and `rsbsa_no` in `farmer_registration` report exports unless explicitly authorized for MAO Head, and log export downloads with column scope.
- **Resolution:** Fixed on `fix/audit-phase-1` (`Report::maskExportRows` masks `contact_number` and `rsbsa_no` to the last 4 digits across CSV, XLSX, and PDF exports unless `$user->isMaoHead()`; CSV, XLSX, and PDF exports log `user_id` and `columns` via `SystemAuditLogger::record`). Verified by `tests/Feature/FarmerRegistrationExportPrivacyTest.php`.

#### SEC-02 — CSP allows `'unsafe-inline'` in `style-src` and `'unsafe-eval'` in `loosePolicy()` ✅ Fixed (`'unsafe-eval'` removed; `style-src 'unsafe-inline'` Deferred)
- **Area:** Security (Headers & CSP)
- **Severity:** **Medium**
- **Evidence:** `app/Http/Middleware/SecurityHeaders.php:65-67` sets `style-src 'self' 'unsafe-inline' https:` in `strictPolicy()` and `'unsafe-inline' 'unsafe-eval'` in `loosePolicy()` (lines 83-91).
- **Impact:** Inline styles remain permitted; if `SECURITY_CSP_STRICT=false` is ever toggled, `'unsafe-eval'` is also re-enabled.
- **Proposed Fix:** Gradually move inline `<style>` / `style=` attributes into bundled CSS so `'unsafe-inline'` can be removed from `style-src`, and remove `'unsafe-eval'` from `loosePolicy()`.
- **Resolution:** `'unsafe-eval'` removed from `SecurityHeaders::loosePolicy()` on `fix/audit-phase-1` (verified by `tests/Feature/SecurityHeadersTest.php`). `style-src 'unsafe-inline'` — **Deferred: low risk, large refactor**.

#### DATA-01 — 2 Pending Migrations & Missing `Schema::hasTable` Guard in `saveOverride()`
- **Area:** Errors / Data
- **Severity:** **High**
- **Evidence:** `php artisan migrate:status` reports `2026_11_22_000001_add_federation_fields_to_farmer_organizations` and `2026_11_23_000001_create_farm_type_yield_overrides_table` as **Pending** on `iclimate_staging_20261103_fix3` (the app DB user `iclimate_app@localhost` lacks `ALTER`/`CREATE` privilege). Meanwhile `app/Http/Controllers/MaoAssociationFarmTypeController.php:64-82` (`saveOverride()`) calls `FarmTypeYieldOverride::query()->create(...)` without checking `Schema::hasTable('farm_type_yield_overrides')` (unlike `clearOverride()` at line 86).
- **Impact:** Submitting the MAO override form before running migrations with a privileged DB user will throw a `500 QueryException`.
- **Proposed Fix:** Run pending migrations with the privileged DB user in staging/production, and add a `Schema::hasTable('farm_type_yield_overrides')` guard in `saveOverride()` returning a friendly `422`/redirect message if missing.

#### DATA-02 — Queue & Scheduler Workers Not Running; Stale Task Runs
- **Area:** Data & Operations
- **Severity:** **High**
- **Evidence:** `ps aux | grep "artisan (queue|schedule)"` shows no active worker; `jobs` table contains `23` pending jobs, `failed_jobs` contains `15` failed jobs, and `scheduled_task_runs` last succeeded on `2026-11-21 18:24:02` (2 days stale relative to `2026-11-23`).
- **Impact:** Background yield prediction requests, weather refreshes, and dashboard warm-ups do not execute automatically unless a worker/scheduler process is running.
- **Proposed Fix:** Ensure `php artisan queue:work` and `php artisan schedule:run` (cron/systemd/supervisor) are active in deployment and inspect/retry or prune the 15 `failed_jobs`.

#### DATA-03 — Municipal-Only Yield Model & Pending Farm-Type Threshold
- **Area:** Data & Model
- **Severity:** **Medium**
- **Evidence:** `docs/model/yield-barangay-audit.md` documents that `rice_yield_model_final.pkl` uses 12 climate/area/season features with no `barangay` or `farm_type` feature; `rice_productions` has 0 verified rows and 0 Rainfed rows; `YieldFarmTypeAdjustment` (`app/Services/Prediction/YieldFarmTypeAdjustment.php:18-24`) requires >= 10 harvests across >= 2 seasons for both `Rainfed` and `Irrigated` before differentiating.
- **Impact:** Until sufficient iClimate harvests are recorded (or MAO sets an optional override), all barangays and farm types show the same Lian-wide seasonal estimate.
- **Proposed Fix:** Continue collecting verified harvests via `/analysis/harvest-training` and retrain `rice_yield_model_final.pkl` once each `(barangay, farm_type, season)` bucket reaches target counts.

#### PERF-01 — Large Frontend Asset Bundles
- **Area:** Performance
- **Severity:** **Medium**
- **Evidence:** `public/build/assets/` contains `app-DRM1wz1K.css` (`544 KB`), `app-eYA68tTN.js` (`332 KB`), `chart-Ce6yGkrZ.js` (`200 KB`), and `leaflet-src-BW0JZ0G8.js` (`146 KB`). (Query counts are well controlled: `PagePerformanceTest` verifies <= 3 queries on cached dashboards and <= 12 queries on uncached pages, and key tables `farmer_organizations`, `farmer_planting_schedules`, and `rice_productions` have indexes on `barangay`, `season`, `farm_type`, `user_id`, `farm_id`, and `verified_at`.)
- **Impact:** Initial cold page load downloads ~876 KB+ of uncached CSS/JS on rural mobile connections.
- **Proposed Fix:** Audit unused Bootstrap/CSS rules in `app.css` and lazy-load heavy charting/mapping modules only on routes that render them.

#### TRANS-01 — Missing Translation Keys Between `lang/en` and `lang/fil`
- **Area:** Translations
- **Severity:** **Medium**
- **Evidence:** Comparing `lang/en/*.php` and `lang/fil/*.php` reveals:
  - `lang/fil/rice_varieties.php` is missing **104** keys (`source.*`, `catalog.*`, `types.*`, etc.)
  - `lang/fil/user_deletion.php` is missing **26** keys (`modal.*`, etc.)
  - `lang/en/farmer.php` is missing **20** `conditions.*` keys present in `lang/fil/farmer.php`
- **Impact:** Filipino users browsing Rice Varieties or account deletion modals see English fallback strings for untranslated keys.
- **Proposed Fix:** Add the missing `fil` translations in `rice_varieties.php` and `user_deletion.php`, and sync `conditions.*` keys in `en/farmer.php`.

#### UX-01 — Residual `"Climora AI"` Decorative Labels
- **Area:** UX & Accessibility
- **Severity:** **Medium**
- **Evidence:** `resources/views/components/ai-chat-launcher.blade.php:19-20`, `resources/views/components/ai-chat-widget.blade.php:608,706,730-731`, `lang/en/farmer.php:241,556`, and `lang/fil/farmer.php:257,570` still display `"Climora AI"` / `"Ask Climora AI"`.
- **Impact:** Inconsistent assistant branding if plain-language non-AI naming is preferred for farmers.
- **Proposed Fix:** Replace `"Climora AI"` / `"Ask Climora AI"` with plain-language farming assistant labels in Blade and both lang files.

#### UX-02 — Hard-Coded English Strings in Layout Blade Partials
- **Area:** UX & Translations
- **Severity:** **Low**
- **Evidence:** `resources/views/layouts/navigation.blade.php:35,109` (`aria-label="Open menu"`, `aria-label="Account menu for ..."`), `resources/views/layouts/mobile-navigation.blade.php:139` (`Close`), and `resources/views/layouts/app.blade.php:376` (`Log out`) contain hard-coded English strings.
- **Impact:** Screen-reader labels and mobile sheet close/logout controls stay in English for Filipino-locale farmers.
- **Proposed Fix:** Move these strings into `lang/en/farmer.php` and `lang/fil/farmer.php` and render via `__(...)`.

#### SEC-03 — `$request->all()` Passed to `validator()` in `RiceVarietyController`
- **Area:** Security / Code Health
- **Severity:** **Low**
- **Evidence:** `app/Http/Controllers/RiceVarietyController.php:349` calls `validator($request->all(), $rules, [], $this->attributeNames())`. (Note: all models use explicit `$fillable`, no model uses `$guarded = []`.)
- **Impact:** Low direct risk since `$validator->validated()` filters keys, but `$request->only(...)` or a FormRequest is safer by convention.
- **Proposed Fix:** Replace `$request->all()` with `$request->only(array_keys($rules))` or extract a FormRequest.

#### HEALTH-01 — Conditionally Skipped Tests
- **Area:** Code Health
- **Severity:** **Low**
- **Evidence:** 5 PHPUnit tests skip on SQLite/macOS (`PagePerformanceTest` pgsql checks, `DatabaseBackupTest`/`OffsiteBackupTest` POSIX/Windows checks, `TimestampRefreshMigrationTest` MySQL check) and 18 Playwright tests skip by viewport (`mobile-375` vs `desktop-1280`) or `API_ML_ACCEPTANCE=1`.
- **Impact:** Informational; expected environment-specific skips.
- **Proposed Fix:** Run MySQL/PostgreSQL CI matrix jobs periodically to cover skipped DB-specific tests.
